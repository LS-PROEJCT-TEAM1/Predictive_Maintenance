## 1. 목적

**충·방전 시험 데이터를 분석해 품질 이상 여부를 담당자가 파악하고, 점검 대상을 판정·기록**하는 대시보드다.
담당자가 "어떤 팩이 → 어느 셀/센서 때문에 → 어떤 불량 유형으로 → 이상인지"를 확인하고 **조치를 결정·기록**하는 흐름을 목표로 한다.

## 2. 설계 근거

### 2.1 요구사항 정의서 (필수 기능 5개)
| ID | 기능 | 상세 요구사항 | 구현 탭 |
|---|---|---|---|
| REQ-01 | 셀 전압, 온도 조회 | 드롭다운 3개(팩 번호 / 충전·방전 / 전압·온도) → 16모듈×11셀(온도 16×2센서) 히트맵, 선택 즉시 최저·평균·최고 갱신, 충전/방전 전압 추세 구분 | 셀 전압·온도 조회 |
| REQ-02 | 이상 셀 판정 | DV = 최고−최저 셀전압, 온도편차 = 최고−최저 온도, 임계값 = 정상 팩 평균+3σ(충전·방전 각각), 이내 OK / 초과 NG | 이상 셀 판정 |
| REQ-03 | 4대 불량 유형 맵핑 | 용량 / 용접 / 센싱와이어 / 센서 불량 카드 4개, 이상 패턴에 맞는 유형 강조, 불량 셀은 히트맵에서 테두리 강조 | 이상 셀 판정 · 셀 조회 |
| REQ-04 | AI 이상 탐지 모델 연동 | anomaly score 시계열 + 임계값 초과 구간 하이라이트, OK/NG 배지, 현재 "모델 연결 대기" → 추후 실제 모델 연동 | AI 이상 탐지 |
| REQ-05 | 판정 이력 다운로드 | 팩 / 모드 / DV / 온도편차 / 판정 결과 로그 테이블, "전체 이력 다운로드" 버튼으로 CSV 저장 | 판정 이력 |

### 2.2 기획서 · 프로젝트 설계서
- 기획서(최우찬 담당): 충·방전별 전압·온도 특성 분석, **정상·이상 구간과 주요 센서 패턴 표시**, Precision·Recall·F1·혼동행렬·오경보율로 검증
- 설계서 5번(Dash 필수 기능): 필터 / 분류 결과 + 혼동행렬 / CSV 업로드·검증·DataTable·다운로드 / 보고서 요약
- 설계서 6~8번: 수행 단계(문제 정의 → 전처리·EDA → 이상 탐지 → Dash 통합 → 보고서), 제출물, 평가 기준(해당 85점)

### 2.3 모델 — PCA (Hotelling T² · SPE) 단일 사용
- 테스트 5개 시험 F1 0.9866, 교차검증 F1 0.8615, Recall 0.976, 오경보율 0.14%
- 관리한계: T² > 20.427 또는 SPE > 2.046, **연속 10시점 이상** 초과 시 이상 구간 확정
- 비지도 방식이라 학습에 없던 불량 유형도 탐지 가능 → 시험마다 불량 유형이 다른 데이터에 적합
- 다른 모델과의 비교는 분석 보고서에 두고, **대시보드에는 PCA 결과만 표시**한다

### 2.4 4대 불량 유형 (Guidebook 불량현상 정의)
| 유형 | 이상 패턴 | 확인 방법 | 조치 | 사례 |
|---|---|---|---|---|
| 용량불량 | 충·방전 중 특정 셀 전압이 급격히 상승/하강 | DV 급증 · 해당 셀 z-score | 불량 셀 모듈 단위 교체 | Test08 |
| 용접불량 | 특정 셀 전압 미측정 또는 셀 전체 전압 저하 | 0V·결측 셀 · 모듈 평균 저하 | 용접부 재검사 | 평가 데이터 내 없음 |
| 센싱와이어불량 | 인접 셀 간 전압 차이 발생 | 같은 모듈 인접 셀 ΔV | 센싱와이어·커넥터 점검 | Test07 |
| 센서불량 | 측정값이 비정상적으로 높거나 낮게 출력 | 물리 범위 이탈 (예: 52V) | 센서 교체 · BMS 파라미터 확인 | Test06 (추정) |

Test05·Test09는 학습용 NG 시험으로 유형 라벨이 없어 "미상"으로 표시한다.

## 3. 전체 구성

### 3.1 레이아웃
- **왼쪽 사이드바**: 통합 현황 · 공급망 예측 · 품질 보증 · 예지 보전 (팀 공통 틀)
- **헤더 가로 탭 6개**: `품질 현황 · 셀 전압·온도 조회 · 이상 셀 판정 · AI 이상 탐지 · 데이터 관리 · 판정 이력`
- **브레드크럼** `품질보증 > 탭명`, 사이드바 "품질 보증" 옆 숫자 배지 = 점검 대기 건수

### 3.2 탭 순서를 이렇게 정한 이유
담당자의 판단 순서(찾기 → 위치 확인 → 기준 판정 → AI 확인 → 기록)를 그대로 따랐다.
1. **품질 현황** — 접속 시 NG 팩부터 파악
2. **셀 전압·온도 조회** — NG 팩의 어느 셀이 문제인지 위치 확인 (REQ-01)
3. **이상 셀 판정** — 3σ 기준으로 OK/NG 근거 확인, 불량 유형 분류 (REQ-02·03)
4. **AI 이상 탐지** — 모델이 짚은 이상 구간·신뢰도 확인 후 점검 판정 (REQ-04)
5. **데이터 관리** — 신규 시험 입력 시에만 사용
6. **판정 이력** — 결과 기록·다운로드 (REQ-05)

"모델 성능" 탭은 PCA 단일 모델만 사용하므로 없앴다. 모델 신뢰도 근거인 **혼동행렬은 AI 이상 탐지 탭으로 옮겨** 판정 직전에 확인하도록 했다.

### 3.3 사용자 흐름
```
① 데이터 관리      CSV 업로드 · 208센서 추출 · 범위 이탈 확인
      ↓
② 품질 현황        DV vs 임계값 막대 · 판정표에서 NG 확인
      ↓ (행 클릭)
③ 셀 전압·온도 조회 드롭다운으로 팩·모드 선택 → 히트맵에서 불량 셀     [REQ-01]
      ↓
④ 이상 셀 판정     3σ 임계 비교 → OK/NG → 4대 유형 매핑             [REQ-02·03]
      ↓
⑤ AI 이상 탐지     score 초과 구간 · 혼동행렬로 신뢰도 확인 · 판정 입력 [REQ-04]
      ↓
⑥ 판정 이력        판정 로그 확인 · 전체 이력 CSV 다운로드            [REQ-05]
```
③ ↔ ④는 양방향 링크("판정 근거 보기" / "히트맵에서 불량 셀 보기")로 연결했다.

## 4. 탭별 기능과 구성 이유

### 4.1 품질 현황
**왜** — 여러 팩 중 어디부터 볼지 한 화면에서 결정한다.

| 기능 | 구성 이유 |
|---|---|
| KPI 5종 (조회 팩 · NG · 점검 대기 · DV 임계값 · 모델 상태) | 상황 → 업무량 → 판정 기준 → 모델 상태 순서 |
| 팩별 평균 DV 막대 + 임계 기준선 (충전/방전 전환) | 교안 px.bar + add_hline. 임계선을 넘은 막대만 포인트 색 |
| 4대 불량 유형 분포 | NG가 어떤 유형에 몰렸는지 파악 |
| 팩별 판정표 → 행 클릭 시 셀 조회로 이동 | DV·온도편차·판정·유형·이상 셀·점검 상태를 한 줄에 |

### 4.2 셀 전압·온도 조회 (REQ-01, REQ-03)
**왜** — 176개 셀 중 문제 위치를 눈으로 찾아야 점검할 수 있다.

| 기능 | 구성 이유 |
|---|---|
| 드롭다운 3개 (팩 번호 / 충전·방전 / 전압·온도) | 요구사항 그대로. 팩마다 가능한 모드만 표시 |
| 히트맵 (전압 16×11 · 온도 16×2) | 회색 농도로 값 크기, **불량 의심 셀만 포인트 색 테두리** (REQ-03) |
| 최저 / 평균 / 최고 / DV(온도편차) | 선택 즉시 갱신. 임계 초과 시 강조 |
| 시점 슬라이더 | 교안 Ch22 slider. 충방전 진행에 따라 셀 값 변화 확인 |
| 충전 vs 방전 전압 추세 | 교안 범주별 px.line. 추세가 반대라 모드 구분이 필수임을 보여줌 |

### 4.3 이상 셀 판정 (REQ-02, REQ-03)
**왜** — OK/NG 판정을 수치 근거와 함께 보여줘야 담당자가 결과를 받아들일 수 있다.

| 기능 | 구성 이유 |
|---|---|
| 판정 기준 (DV·온도편차 계산식, 모드별 평균·σ·임계값 표) | 판정 규칙을 화면에 공개 |
| 판정 대상 선택 → DV / 온도편차 / OK·NG 결과 | 어떤 기준을 넘었는지(DV / 온도 / 둘 다) 표시 |
| 정상 팩 분포 히스토그램 + 3σ 임계선 + 대상 팩 위치 | 교안 px.histogram + 평균±3σ (Ch46). 임계값이 정상 분포에서 나온 근거 |
| DV × 온도편차 산점도 (임계 초과 영역 음영) | 교안 px.scatter color·hover. 두 기준을 동시에 비교 |
| 4대 불량 유형 카드 | 해당 유형만 강조, 확인 방법·조치·사례 제시 → 히트맵 링크 |

### 4.4 AI 이상 탐지 (REQ-04)
**왜** — 3σ 규칙(팩 평균)이 놓치는 **시점별 이상 구간**을 PCA 모델로 짚고, 판정을 입력한다.

| 기능 | 구성 이유 |
|---|---|
| 모델 상태 배지 (연결 대기 ↔ 연결됨) | 요구사항대로 기본은 "모델 연결 대기". 연결 시 결과 표시 |
| Anomaly score 시계열 + 이동평균 + 임계선 + 초과 구간 하이라이트 | 교안 px.line + rolling (Ch45) + add_hline. SPE 기본, T² 전환 |
| 예측 vs 라벨 스트립 · 임계 초과 구간 목록 | 연속 10시점 확정 규칙 명시 |
| OK/NG 배지 · 규칙 판정과 비교 | 3σ 규칙과 AI 판정이 일치하는지 교차 확인 |
| 기여 이상 셀 Top 5 | 점검할 셀 목록 |
| **혼동행렬 (PCA 테스트)** | TN 7,283 · FP 10 · FN 82 · TP 3,395. 판정 직전에 오경보·누락 규모 확인 (모델 성능 탭에서 이동) |
| 점검 판정 4종 + 메모 | 입력 결과는 품질 현황·판정 이력에 즉시 반영 |

### 4.5 데이터 관리
**왜** — 설계서 5번 "CSV 업로드·검증" 필수 기능. 예지보전 화면과 같은 4단계 구조로 통일.

| 기능 | 구성 이유 |
|---|---|
| 4단계 진행 바 (업로드 → 검증 → 전처리 → 분석 실행) | 어느 단계에서 문제가 생겼는지 파악 |
| 검증 결과 7항목 | 231→208 컬럼, 물리 범위 이탈, **BMS 요약 컬럼 제외(누수 방지)**, 결측·중복, 라벨 행 수 |
| 전처리 전/후 · Feature 9개 | 설계서 6번 "처리 전후 근거 기록" 대응 |

### 4.6 판정 이력 (REQ-05)
**왜** — 판정 결과를 남기고 외부로 전달해야 점검 업무가 끝난다.

| 기능 | 구성 이유 |
|---|---|
| KPI (판정 이력 · NG · 재검사 요청 · 점검 대기) | 처리 현황 요약 |
| 로그 테이블 (일시 · 팩 · 모드 · DV · 온도편차 · 판정 · 유형 · 조치 · 메모) | 교안 dash_table.DataTable (Ch31) |
| 충방전 · 판정 필터 | 필요한 이력만 조회 |
| **전체 이력 다운로드** · 필터 결과 CSV | 실제 CSV 파일 저장 동작 (UTF-8 BOM, 엑셀 호환) |
| 핵심 결론 · 한계 | 설계서 5번 보고서 요약 대응 |
