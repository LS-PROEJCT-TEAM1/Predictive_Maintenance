## 1. 목적

대시보드의 목적은 **충·방전 시험 데이터를 분석해 품질 이상 여부를 담당자가 파악하고, 점검 대상을 판정·기록**하는 것이다.
단순히 그래프를 보여주는 화면이 아니라, 담당자가 "어떤 시험이 → 언제 → 어느 셀/센서 때문에 → 이상인지"를 확인하고 **조치를 결정**하는 흐름을 목표로 했다.

## 2. 설계 근거 (참고 문서에서 추출한 요구사항)

### 2.1 기획서 최종본 — 최우찬 담당 범위
- 담당 영역: 배터리팩 품질보증 AI — 충·방전 데이터 분석, 품질 이상 분류·탐지
- 구현 방향: 충·방전별 전압·온도 특성을 분석하고 **정상·이상 구간과 주요 센서 패턴 표시**
- 모델 후보: Decision Tree·Random Forest, PCA (2개 이상 비교, 누락·오경보 함께 평가)
- 검증 지표: Precision·Recall·F1, 혼동행렬, 오경보율
- 기대효과: 설비·품질 담당자가 **이상 구간과 관련 센서를 확인해 점검 대상 선정**

| 설계서 항목 | 품질보증 적용 내용 |

### 2.3 모델 결과 (`배터리 품질보증 모델/output`)
- 채택 모델: **PCA (Hotelling T² · SPE)** — 테스트 F1 0.9866, 교차검증 F1 0.8615, 불량 3유형 모두 탐지
- 관리한계: T² > 20.427 또는 SPE > 2.046, **연속 10시점 이상** 초과 시 이상 구간 확정
- Random Forest는 학습에 없던 유형(Test06 전압 센서 고장)을 전혀 탐지하지 못함 → 시험마다 불량 유형이 달라 **비지도 방식이 적합**
- 대시보드는 `model_C_pca_t2_spe_이상점수.csv`, `_이상셀순위.csv` 등 output CSV를 그대로 읽는 구조로 설계

## 3. 전체 구성

### 3.1 레이아웃
- **왼쪽 사이드바**: 통합 현황 · 공급망 예측 · 품질 보증 · 예지 보전
  → 팀 공통 틀. 세 담당 모듈을 하나의 Control Tower에서 이동하도록 통일
- **헤더 가로 탭 (품질 보증 선택 시)**:
  `품질 현황 · 이상 구간 탐지 · 데이터 탐색 · 데이터 관리 · 모델 성능 · 점검 리포트`
- **브레드크럼**: `품질보증 > 탭명` — 현재 위치를 항상 표시
- 사이드바 "품질 보증" 옆 숫자 배지 = **점검 대기 건수** (판정 입력 시 감소)

### 3.2 탭 순서를 이렇게 정한 이유
매일 쓰는 화면을 앞에, 준비·근거·마무리 화면을 뒤에 두었다.
1. **품질 현황** — 접속 시 가장 먼저 "오늘 점검할 것"을 봐야 하므로 첫 탭
2. **이상 구간 탐지** — 실제 판단이 일어나는 핵심 화면
3. **데이터 탐색** — 판단 중 정상 범위와 비교할 때 이동
4. **데이터 관리** — 신규 시험 데이터 입력 시에만 사용
5. **모델 성능** — 판정 결과의 신뢰도 근거
6. **점검 리포트** — 결과 정리·다운로드

탭 이름은 예지보전 담당 화면과 맞춰 **데이터 탐색 / 데이터 관리**로 통일했다.

### 3.3 사용자 흐름
```
① 데이터 관리      신규 시험 CSV 업로드 · 검증 · 전처리
      ↓
② 품질 현황        KPI · 시험별 판정표에서 NG·경보 시험 식별
      ↓ (행 클릭)
③ 이상 구간 탐지   SPE 시계열 · 이상 구간 · 이상 셀 · 센서 패턴 → 점검 판정 입력
      ↕ (비교 링크)
④ 데이터 탐색      같은 충/방전 정상 팩 범위와 대조
      ↓
⑤ 모델 성능        판정 신뢰도 근거 확인
      ↓
⑥ 점검 리포트      조치 이력 · 결론 · 한계 → PDF / CSV
```
③ ↔ ④는 양방향 링크로 연결했다. 담당자는 이상을 본 뒤 "정상 팩과 비교"하고, 다시 돌아와 판정하는 경우가 많기 때문이다.

## 4. 탭별 기능과 구성 이유

### 4.1 품질 현황
**왜** — 담당자가 수많은 시험 중 어디부터 볼지 한 화면에서 결정해야 한다.

| 기능 | 구성 이유 |
|---|---|
| KPI 5종 (평가 시험 · 이상 판정 · 이상 구간 시점 · 점검 대기 · F1/오경보율) | 상황 파악 → 업무량 → 모델 신뢰도 순서로 배치. 설계서 8번 "필터와 KPI 일관 갱신" 대응 |
| 시험별 판정표 (모델 판정 · 이상 구간 비율 · 주요 이상 셀 · 추정 유형 · 점검 상태) | 판정만이 아니라 **어디를(셀) 왜(유형)** 까지 표에서 바로 보이게 해 드릴다운 전 우선순위 결정 가능 |
| 점검 상태 배지 (대기 / 재검사 요청 / 정상 처리 / 보류) | 탐지에서 끝나지 않고 **조치 진행 상황**을 추적하기 위함 |
| 충방전별 OK vs NG 평균 비교 | 충전·방전 특성이 달라 따로 봐야 한다는 분석 결과(`02_충방전별_EDA.csv`)를 요약 |
| 오늘 점검 순서 | 이상 구간 비율·유형 심각도 기준으로 점검 순서 제안 |
| 행 클릭 → 이상 구간 탐지 | 표에서 바로 상세 화면으로 이동 (기획서 "시험 선택 → 상세 조회") |

### 4.2 이상 구간 탐지 (핵심 화면)
**왜** — 기획서의 "정상·이상 구간과 주요 센서 패턴 표시"를 직접 구현하는 화면. 점검 판정도 근거를 보는 이 화면에서 바로 입력한다.

| 기능 | 구성 이유 |
|---|---|
| 시험 선택 칩 · SPE / T² 지표 전환 | SPE가 탐지력의 대부분(Recall 0.976 vs T² 0.465)이라 **SPE를 기본값**으로, T²는 비교용 |
| 이상 점수 시계열 + 관리한계 점선 + 이상 구간 음영 | README "대시보드 연동" 가이드 그대로: `시점 × SPE`, 관리한계 점선, `예측==1` 하이라이트 |
| 예측 vs 실제 라벨 스트립 | Test07처럼 라벨이 일부 구간에만 있는 경우 오탐/누락을 눈으로 확인 |
| 이상 구간 목록 (연속 10시점 확정) | 운영 규칙(단발 잡음 억제)을 화면에 명시해 판정 기준을 투명하게 |
| 셀 전압 z-score Heatmap (16 모듈 × 11 셀) | 176개 셀 중 **어느 위치**가 이상인지 한눈에. \|z\| ≥ 2만 포인트 색으로 칠해 색 사용 최소화 |
| 이상 셀 Top 5 | `_이상셀순위.csv` 기반, 점검할 셀 목록을 바로 제공 |
| 주요 센서 패턴 (셀 vs 팩 중앙값) | 이상 셀이 **팩 내 다른 셀과 어떻게 벌어지는지** 보여줌. "관계가 먼저 깨진다"는 분석 결론을 시각적으로 설명 |
| 점검 판정 4종 + 메모 | 탐지 → 판단 → 기록까지 한 화면에서 끝내기 위함. 입력 결과는 품질 현황·리포트에 즉시 반영 |

### 4.3 데이터 탐색 (충방전 특성)
**왜** — 이상 판단에는 "정상이 어떤 모양인지"라는 기준이 필요하다. 충전·방전은 전압·온도 거동이 다르므로 분리해서 비교한다.

| 기능 | 구성 이유 |
|---|---|
| 충전 / 방전 토글 | 파일 단위로 충방전을 분리 분석한 모델 설계와 동일 |
| 셀 전압 편차 DV 곡선 (정상 팩 5개 회색 + NG 시험 포인트 색) | 정상 팩 묶음을 회색 배경으로, NG만 색을 입혀 **벗어난 지점만 눈에 띄게** |
| 모듈 온도 편차 곡선 | Test08(모듈 온도 불균형) 같은 온도 유형 확인용 |
| 진행률 슬라이더 (두 그래프 커서 동시 이동) | 같은 진행 시점의 정상/NG 값을 정확히 비교 |
| OK vs NG 특성 요약표 | 설계서 8번 "데이터 품질·EDA" 평가 근거 |
| 해석 가이드 · 이상 구간 탐지로 복귀 링크 | 절대값이 아닌 **팩 내부 상대 편차**로 판단한다는 원칙 안내 |

### 4.4 데이터 관리
**왜** — 설계서 5번 "CSV 업로드·검증, DataTable, 필터, 다운로드" 필수 기능. 팀 예지보전 화면과 같은 4단계 구조로 통일했다.

| 기능 | 구성 이유 |
|---|---|
| 4단계 진행 바 (파일 업로드 → 검증 → 전처리 → 분석 실행) | 입력 과정을 단계로 보여 어디서 문제가 생겼는지 알 수 있게 함 |
| 업로드 · 파일 정보 (시험 · 라벨 · 행 수 · 모드) | 라벨은 선택 사항. 파일명으로 충/방전 자동 구분 |
| 검증 결과 표 (항목 · 결과 · 건수 · 설명) | 실제 전처리 규칙을 그대로 반영: 231 → 208 컬럼 추출, 물리 범위(2.0~5.0V, −20~100℃) 이탈, **BMS 요약 컬럼 제외(데이터 누수 방지)**, 결측·중복, 라벨 행 수 일치. 경고 행만 강조 |
| 전처리 전/후 | 설계서 6번 "처리 전후 결과와 근거 기록" 대응 |
| Feature 생성 (9개 상대 특성) | 셀 전압 편차·σ·3σ 이탈 셀 수·최대 z-score, 모듈온도 편차·σ, 변화율 등 — 모델 입력을 투명하게 공개 |
| 데이터 요약 테이블 + 충방전·판정 필터 + CSV 다운로드 | `00_데이터_요약.csv` 기반. 학습/평가 파일 구분까지 보여 **파일 단위 분리(누수 방지)** 를 확인 |

### 4.5 모델 성능
**왜** — 담당자가 판정을 믿으려면 근거가 필요하고, 설계서 평가 기준(분류·이상 탐지 20점)의 핵심 항목이다.

| 기능 | 구성 이유 |
|---|---|
| 모델 5종 비교표 (Precision · Recall · F1 · 교차검증 F1 · 불량 3유형) | 설계서 "2개 이상 모델 비교", 정확도만이 아닌 지표 제시. 채택 모델 행 강조 |
| 혼동행렬 (TN 7,283 · FP 10 · FN 82 · TP 3,395) | **오경보(FP)와 누락(FN)** 을 따로 강조. 기획서 "이상 누락과 오경보 균형" 평가 대응 |
| 불량 유형별 탐지율 (PCA · RF · IF · LSTM) | RF가 Test06을 0% 탐지한다는 사실로 **비지도 PCA 채택 이유**를 설명 |
| 운영 설정 (정상 학습 행 수 · 주성분 · 관리한계 · 연속 시점) · T² vs SPE 단독 성능 | 판정 기준을 재현 가능하게 공개 (재현성 평가 대응) |

### 4.6 점검 리포트
**왜** — 설계서 5번 "보고서 요약: 핵심 결론·한계·개선 제안"과 7번 제출물(보고서) 대응. 점검 결과를 외부로 전달하는 마지막 단계.

| 기능 | 구성 이유 |
|---|---|
| 핵심 결론 | 모델 선정 결과와 "SPE = 관계 붕괴 탐지" 인사이트를 한 문단으로 |
| 점검 대상 · 조치 이력 (판정 · 메모) | 이상 구간 탐지에서 입력한 판정이 그대로 모임 |
| 한계 · 개선 제안 | 셀 단위 라벨 부재, Test07 라벨 범위, 정상 기준 데이터 수(10/102) 등 README 한계 반영 |
| PDF · 이상 점수 CSV · 점검 이력 CSV 다운로드 | 기획서 "분석 요약과 결과를 CSV 또는 보고서로 저장" 대응 |

- 기본은 무채색이고, **포인트 색은 "봐야 할 곳"에만** 사용한다. 정상 데이터는 회색, 이상만 teal이다.
- 그래프에서도 정상 팩은 회색, NG만 색을 입혀 비교 대상이 자동으로 눈에 띄게 했다.
- 선·표 구분선은 팔레트 회색의 아주 옅은 톤(`#E4E4E6`, `#F0F0F1`)으로만 추가했다.

### 5.2 타이포 · 레이아웃
- IBM Plex Sans KR(본문) + IBM Plex Mono(수치·파일명·셀 ID). 수치는 고정폭으로 정렬
- 모든 카드는 흰 배경 + 둥근 모서리, 테두리 없이 배경 대비로 구분 (팀 시안 기준)
- 판단 영역(점검 판정, 내보내기)만 teal 윤곽선으로 구분
