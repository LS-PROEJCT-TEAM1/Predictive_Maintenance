# 모델별 스크립트 실행 결과 — 정상 기준 데이터 10개 파일 적용

BatteryFlow AI Control Tower · 배터리 품질 모듈 · 담당 최우찬 · 2026.09.23

## 바뀐 점

기존에는 정상(OK) 기준 데이터가 **시험 2건(2,742행)** 뿐이었다. 이번에는 `data/preprocessed/train`의 **10개 파일(56,805행)** 을 정상 기준으로 썼다.

| | 이전 | 이번 |
|---|---|---|
| 정상 기준 데이터 | Test01, Test02 — 2,742행 | 1000~1004의 chg/dchg 10개 — **56,805행** |
| 충방전 구성 | 충전 1 + 방전 1 | 충전 5 + 방전 5 |
| 지도학습 학습 데이터 | 12,622행 | 66,685행 |

충전 5 + 방전 5로 고른 이유는 평가 대상이 충전(Test03·06·08)과 방전(Test04·07) 양쪽이기 때문이다.

### Test07 문제가 사라졌다

이전 분석에서 오탐의 80%가 Test07에서 나왔다. NG 팩인데 라벨이 마지막 227시점에만 붙어 있어, 앞 구간 4,367시점이 전부 오탐으로 잡혔기 때문이다.

이번에는 **네 모델 모두 Test07의 정상 구간 4,367시점을 정상으로 맞혔다(FP=0).** 정상 기준을 실제 정상 운전 데이터 56,805행에서 잡으니, Test07의 앞 구간이 "정상 범위 안"으로 제대로 판정된 것이다. 이전의 오탐은 모델 문제가 아니라 **정상 기준 데이터가 부족해서 생긴 문제**였다.

그래서 이제는 Test07 제외 여부와 관계없이 지표를 그대로 쓸 수 있다.

## 모델별 운영 기준

### 3σ 규칙 (주 모델)

```
모듈온도_편차 > 3.6928 ℃  또는  셀전압_최대z > 3.8568  → 이상
```

정상 데이터 56,805행의 평균 + 3×표준편차로 산출했다. 변수별 단독 성능은 이렇다.

| 변수 | 3σ 임계값 | Precision | Recall |
|---|---|---|---|
| 모듈온도_편차 | 3.6928 ℃ | 1.0000 | 0.689 |
| 셀전압_최대z | 3.8568 | 0.9800 | 0.310 |
| 셀전압_편차 | 0.0327 V | 0.9908 | 0.031 |
| 이상셀_개수 | 2.8982개 | 0.1808 | 0.278 |

온도 편차가 Test08(온도 불균형)을, 셀전압 최대z가 Test06·07(셀 전압 이탈)을 담당한다. 두 규칙을 OR로 묶어야 Recall 0.999가 나온다.

### PCA 이상탐지 (보조)

- 정상 56,805행으로 적합 → 주성분 6개, 누적 설명분산 97.51%
- 임계값: 정상 데이터 99% 분위수 (Q > 2.046 또는 T² > 20.427)
- 연속 10시점 이상 초과할 때만 이상 구간으로 확정
- 오탐이 10건으로 가장 적다. 이상 점수를 연속값으로 주므로 Heatmap 색상에 바로 쓴다.

### Decision Tree — 학습된 판정 규칙

```
모듈온도_편차 <= 3.75
├─ 셀전압_표준편차 <= 0.01
│  └─ 셀전압_최대z > 4.18 & 셀전압_편차 > 0.01 → 이상
└─ 셀전압_표준편차 > 0.01
   └─ 모듈온도_표준편차 <= 0.31 & 셀전압_최대z > 2.09 → 이상
모듈온도_편차 > 3.75 → 이상
```

트리가 스스로 찾은 기준(3.75℃)이 3σ 규칙의 임계값(3.69℃)과 거의 같다. **두 방법이 같은 물리 현상을 가리킨다**는 교차 확인이 된다. 발표 자료에 쓰기 좋은 근거다.

## 결론

1. **주 모델은 3σ 규칙** — Recall 0.9991로 놓치는 구간이 3개뿐이고, 임계값 2개로 설명된다.
2. **보조는 PCA** — 오탐이 가장 적고, 규칙이 다루지 않는 새 불량 유형에 반응한다.
3. **Decision Tree는 검증·설명용** — 트리가 찾은 3.75℃ 기준이 3σ 임계값과 일치해 규칙의 타당성을 뒷받침한다.
4. **Random Forest는 이번 데이터에서 이점이 없다** — Decision Tree와 성능이 사실상 같고(차이 0.0005), 해석은 더 어렵다. 파일 단위 교차검증 F1이 0.447±0.422로 여전히 크게 흔들린다.
5. **가장 큰 교훈은 모델이 아니라 데이터였다.** 같은 알고리즘, 같은 Feature인데 정상 기준 데이터를 2,742행에서 56,805행으로 늘린 것만으로 Precision이 0.37 → 0.9996으로 올랐다.

## 남은 한계

- 지도학습(DT/RF)은 학습하지 않은 불량 유형(Test06 센서 고장)을 놓친다. 학습용 NG 시험이 2건뿐인 게 원인이다.
- 셀 단위 정답 라벨이 없어 기획서의 "이상 **셀** 판별 Precision"은 여전히 시점 단위로 대체 측정했다.
- 정상 기준 데이터를 더 늘릴 여지가 있다(현재 10개 / 전체 102개).
