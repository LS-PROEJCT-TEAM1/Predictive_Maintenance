## 판정

**학습된 모델과 저장 성적의 일관성은 확인했다. 그러나 데이터 대표값 결정, 기준모델 비교, 시험 결과를 이용한 부품별 모델 선택에 문제가 있어 ‘최적 모델 선정과 독립 검증이 완료됐다’고 판단할 수 없다.**

공식 `purged_v1`의 시간 분할과 train-only 전처리는 적절하다. 다만 이 평가 이후 대시보드용 산출물을 만드는 경로와 연관 부품 모델에서 시험 세트가 선택에 다시 사용된다. 기존 성적을 전부 무효로 볼 필요는 없지만, 고정 모델의 점수와 사후 선택 조합의 점수를 구분해야 한다.

이번 작업은 감사다. 원본 XLS, 기존 학습 코드, 모델, 평가 결과, 시드, 앱 설정을 변경하지 않았고 재학습·Firestore 접근·GitHub 업로드도 하지 않았다. 감사용 파일과 본 보고서만 추가했다.

## 2. 우선 수정이 필요한 발견 사항

### P1 — 최종 시험 결과로 부품별 운영 모델을 선택함

**주요 경로:** `src/build_dashboard_assets.py:233`은 최종 holdout에서 계산한 부품별 MAE로 XGBoost와 이동평균 중 더 좋은 모델을 선택해 `recommended_model`에 저장한다. `app.py:57`의 `with_operating_forecast`는 이 선택을 실제 표시 예측으로 사용한다.

현재 `outputs/dashboard_data/csv/parts.csv`는 XGBoost 70개, 이동평균 41개 부품을 선택한다. 이 사후 선택 조합을 같은 764건에 적용하면 MAE는 24.7058이다. 이 값은 **선택에 사용한 시험 데이터에서 계산한 값**이며, 해당 조합의 미관측 데이터 성능이 아니다. 시험 표본이 1건인 부품도 선택 대상이다.

**연관 부품 경로:** `src/train_related_part_model.py:289~315` 역시 holdout MAE로 기본 모델을 고르고, 5건 이상·2% 개선 조건으로 30/111개 부품의 연관 모델 사용을 활성화한다. 한 부품당 최대 7건인 시험에서 고른 규칙을 별도 기간에서 검증하지 않았다.

추가로 연관 후보 상관관계는 `relation_end=2021-10-22`까지 사용하지만, 해당 모델의 학습 목표 마지막 날은 10-14, 검증 목표 기간은 10-18~21이다. 따라서 상관관계 기반 변수 선택이 학습/검증 구분보다 먼저, 검증 기간까지 포함해 이뤄진다. 최종 시험 목표값을 상관관계 계산에 직접 포함한 것은 아니지만, 검증 단계의 독립성은 깨진다.

영향 범위는 구분해야 한다. **루트 통합 앱**의 `backend/data.py:61`, `backend/main.py:124`와 `src/inference.py`는 기본 이동평균을 사용한다. 따라서 기존 전용 앱의 사후 선택 오류가 통합 앱 기본 예측에도 그대로 적용된다고 판단하지 않는다.

수정 방향: 부품별 모델과 활성화 규칙을 과거 검증 또는 과거 out-of-fold 결과만으로 고정한다. 연관 후보도 각 학습 구간 안에서 산출한다. 고정된 선택을 이후 미사용 기간에 한 번 평가한다. 고정 모델 성적과 선택 조합 성적을 별도로 표기한다.

### P1 — 동일 시각 충돌을 엑셀 행 순서로 결정함

`src/train_evaluate_purged_models.py:47,97~104`는 `row_id`로 동률을 정렬한 뒤 마지막 행을 사용한다. 실행 결과는 결정적이지만, 그 행이 업무상 올바른 최종값이라는 근거는 없다.

예: Sheet1의 `Part 21`, `2021-09-13 18:30`은 Excel 23행에서 당일 수량 360, 74행에서 0이다. 현행 코드는 0을 선택한다. 두 행이 수정 이력인지, 식별자 충돌인지, 별도 수요인지 원본 필드만으로 확정할 수 없다.

동률 중 앞/뒤 행 선택을 바꾸면 당일 정답은 CV 30건, 최종 시험 14건에서 바뀐다. 입력 시퀀스도 각각 30건, 14건에서 충돌 행을 포함한다. 모든 부품의 데이터가 잘못됐다는 의미는 아니지만, 이 상태에서 정답 정의가 완전히 검증됐다고 말하기 어렵다.

수정 방향: 충돌 그룹을 별도 목록으로 보존하고 원천 식별자·수정 순서 근거를 확인한다. 확인 전에는 충돌 부품 제외 또는 여러 처리 정책의 민감도 결과를 함께 제시한다. 합산·평균·최댓값으로 임의 확정하지 않는다.

### P1 — 가장 단순한 최근값 기준모델이 빠져 최선이라는 결론이 불충분함

`src/train_evaluate_final_models.py:38`의 현재 후보에는 최근값 유지 예측이 없다. 루트 설계서 4쪽은 최근값·이동평균 같은 기준 예측과 후보모델 비교를 요구한다. 이동평균을 포함했으므로 기준모델 요건 자체는 충족하지만, 운영 모델이 최선이라는 주장을 하려면 최근값도 확인할 필요가 있다.

원본에서 `예측(D+3)=기준일 D의 당일 수량`을 재구성해 같은 표본에 적용한 결과:

| 예측 방법 | CV MAE, N=1,614 | 최종 시험 MAE, N=764 |
|---|---:|---:|
| 최근값 유지 — 이번 감사 추가 비교 | **35.8445** | 30.5445 |
| 3일 이동평균 | 36.9523 | 31.8647 |
| XGBoost | 48.3896 | 27.0047 |
| CatBoost | 58.7870 | **25.3149** |
| LightGBM | 69.4124 | 27.6609 |
| LSTM | 59.5771 | 61.4988 |
| D+3 계획량 | 52.2949 | 30.4476 |

최근값 유지의 CV MAE는 이동평균보다 약 3.00% 낮다. 다만 CV RMSE는 최근값 82.8135, 이동평균 80.5389로 이동평균이 낫다. 최근값은 세 fold 중 첫 fold에서만 MAE가 더 낮으며, 나머지 두 fold는 이동평균이 낫다. **이번 비교만으로 최근값이 통계적으로 우월하거나 즉시 운영 모델로 교체해야 한다고 결론 내리지 않는다.**

동일 요일의 지난주 수량을 쓰는 기준도 확인했다. CV 1,614건 MAE 46.4213이다. 최종 시험에서는 지난주 자료가 있는 755건만 계산 가능하므로 전체 764건과 직접 순위 비교하지 않았다.

수정 방향: 최근값·이동평균·계획량을 사전 정의한 공통 기준에 포함하고 MAE/RMSE의 우선순위와 기간별 안정성을 함께 평가한다. 이번 추가 비교 역시 이미 관찰한 데이터에 대한 감사 결과이므로 새 독립 시험을 대체하지 않는다.

### P2 — ‘독립 holdout’의 의미를 실험 전체로 확장할 수 없음

현재 `train_evaluate_purged_models.py`의 코드 흐름은 CV 결과로 모델을 선택한 후 최종 시험을 계산한다. 이 실행 내부의 선택·시험 구분은 확인됐다.

그러나 현 최종 시험 764개 부품·목표일 키 전부가 이전 `final_model_evaluation/predictions_test.csv` 및 `final_walk_forward/predictions_walk_forward.csv`에도 존재한다. 이후 대시보드와 연관 모델은 이 기간의 성적을 선택에 사용한다.

따라서 ‘현재 실행에서 학습에 쓰지 않은 시간 분리 시험’은 맞지만, 프로젝트 개발 전체에서 한 번도 보지 않은 완전히 새로운 시험이라고 보증할 수 없다. 과거 점수를 보고 실제로 초매개변수를 조정했는지는 저장 파일만으로 확정하지 못했다. 직접적인 목표값 학습 누수와 개발 과정의 반복 참조 위험을 구분한다.

수정 방향: 기존 마지막 구간은 회고 평가로 명확히 기록한다. 이후 수집 데이터로 미관측 최종 평가를 확보하거나, 추가 데이터가 없으면 사전 고정된 중첩 시간 검증과 한계를 보고한다. 이미 본 데이터를 파일명만 바꿔 새 독립 시험이라고 부르지 않는다.

### P2 — 학습 설계는 합리적 출발점이나 최적화 완료 근거는 부족함

- 현재 purged 평가의 실제 학습 목표 날짜는 fold별 10·15·20일, 최종 모델은 28일이다. 조기 종료 검증은 매번 3일뿐이다. 행 수 1,104·1,655·2,220건을 독립적인 긴 시계열 관측으로 해석하면 안 된다.
- 첫 fold의 LightGBM은 1개 트리, CatBoost는 3개 트리에서 선택됐다. 이것만으로 구현 실패를 뜻하지는 않지만, 짧은 검증 구간에 대한 조기 종료 민감도를 확인해야 한다.
- XGBoost의 fold MAE는 48.51 → 71.62 → 24.28이다. 통합 평균 한 개로 안정적인 우수 모델이라고 말하기 어렵다.
- 초기 분석 계획의 lag7·rolling7·계획 수정량 등은 이전 `train_evaluate_models.py`에 구현되어 있다. 그러나 현재 공식 파이프라인은 최근 3일의 4개 원변수 + 날짜 5개 + 부품 ID만 사용한다. **계획 전체가 미구현인 것은 아니며, 확장 특징의 효과를 현재 누수 방지 분할에서 비교한 근거가 부족한 상태다.**
- 현재 파이프라인에는 모델별 고정 초매개변수와 조기 종료가 있다. 체계적인 후보 범위 비교, 특징 추가/제거 비교, 다중 seed 안정성 결과는 확인되지 않았다.
- 트리 모델은 원 수량 MAE로 조기 종료하지만 LSTM은 log1p 목표를 표준화한 SmoothL1 검증 손실로 epoch를 선택한다(`train_evaluate_final_models.py:426~477`). 학습 방식으로 가능하지만 최종 선정 지표인 원 수량 MAE와 일치하지 않는다. 원 수량 MAE 기준 체크포인트도 비교해야 LSTM에 대한 결론이 더 공정해진다.

수정 방향: 먼저 데이터 정책과 평가 절차를 고정한다. 그 후 같은 시간 분할에서 특징 집합·단순 기준·소규모 초매개변수 후보를 비교한다. 이미 여러 모델이 있으므로 모델 종류를 무작정 늘리는 것이 우선은 아니다.

### P2 — 예측 오차를 재고 보장으로 해석할 근거가 없음

연관 부품 코드와 기존 전용 앱은 전체 CV 이동평균 MAE 36.9523을 모든 부품의 준비 수량에 더한다. 이는 검증된 서비스 수준이나 부품별 안전재고가 아니다.

실제 최종 시험에서 `ceil(이동평균 + 36.9523)`이 당일 수량 이상인 비율은 90.18%였다. 이 값도 재고 품절률이 아니라 단일 목표일 수량에 대한 단순 경험적 포함률이다. 재고·입고 예정·리드타임·부족 비용이 없어 최적 발주량/재고비용 개선을 검증할 수 없다.

또한 하루 마지막 로그를 입력으로 쓰므로 이 결과는 해당 로그 확보 이후의 예측이다. 오전 발주 업무에 그대로 적용할 경우 당일 오후에 갱신된 입력을 쓸 수 없다. 예측 실행 시각과 데이터 확정 시각을 입력 계약에 포함해야 한다.

수정 방향: 당분간 수요 예측/준비량 참고치로 명시한다. 목표 서비스 수준이 필요하면 과거 검증 잔차로 구간을 보정하고 미사용 기간에서 포함률을 확인한다. 실제 재고 최적화와 분리한다.

## 3. 정상적으로 확인된 부분

1. **가이드북과 문제 정의 정합성:** 부품·날짜별 마지막 로그, 연속 3일의 당일량/D+3·4·5 계획량, D+3 목표는 설명 가능한 설계다. 다부품 전역 모델과 부품 인코딩은 가이드북 Part 94 예제에서 확장된 설계다.
2. **현재 공식 경계:** 재구성한 원본 Total 4개 분할은 `train target < validation origin`, `validation target < test origin`을 만족한다. 저장 감사표의 두 시나리오 8개 분할도 자동검사를 통과했다.
3. **전처리:** 원핫 인코더, LSTM 입력·날짜 스케일러, 목표 로그 평균·표준편차가 train에서만 계산된다. 신경망의 학습 배치 shuffle은 시간 분할 이후 학습 표본에만 적용되어, 이것 자체를 시간 분할 누수로 보지 않는다.
4. **정답 정렬:** 원본 Total CV 1,614건과 최종 시험 764건의 목표값 및 D+3 계획 기준값 모두 원본과 일치한다. 모든 목표일은 기준일 +3 달력일이다. 이동평균 오차는 float32 반올림 수준, 최대 약 0.000021개다.
5. **지표:** 저장 예측에서 계산한 MAE/RMSE/WAPE/Bias는 저장 표와 약 0.0000003 이내로 일치한다. 기존 자동검사는 R² 재계산까지 두 시나리오 모두 통과했다.
6. **저장 모델 재추론:** 최종 시험 764건 전부에서 XGBoost 최대 차이 약 0.000027개, LightGBM·CatBoost 약 5.7e-14개다. CSV 추론 모듈의 XGBoost도 동일하다. 배포용 `runtime/demand`의 모델·전처리기·메타데이터 해시는 원 학습 산출물과 같다.
7. **설계서 기본 요건:** 기준 예측, 복수 지도학습 후보, 시간 분할, MAE/RMSE, 부품별 오차 산출물, 짧은 기간의 한계 기록은 존재한다. 특정 최신 모델을 반드시 써야 한다는 요건은 없다.

## 4. 과거 실험 및 문서 해석 주의

- `guidebook_reproduction`은 교재 비교 실험이다. Part 94/95의 44개 시퀀스를 행 순서로 자르며, 10-31 누락 때문에 1개 목표의 실제 간격은 4일이다. 학습 목표 종료 10-17이 첫 검증 기준일 10-15보다 늦고, 검증 목표 종료 10-22가 첫 시험 기준일 10-20보다 늦다. 이 결과를 현재 purged D+3 운영 성적과 같은 수준의 검증으로 제시하면 안 된다.
- 현재 최종 모델은 달력 날짜로 목표를 찾으므로 위 행 순서 horizon 문제를 해결했다.
- README와 purged 보고서의 ‘두 수량 정의에서 순위 동일’은 정확히는 **전체 1위 이동평균 및 ML 1위 XGBoost가 동일**하다는 뜻이다. CatBoost와 LSTM의 나머지 순서는 두 시나리오에서 바뀐다.
- `EXCLUDED_PARTS={'Part 115'}`와 추론의 시작일 `2021-09-13`이 고정되어 있다. 현 스냅샷에는 맞지만 새 원본 버전의 일반적인 재학습 파이프라인으로 쓰려면 데이터 계약/메타데이터로 옮겨야 한다.
- 저장 모델에 일부 라이브러리 버전은 있지만 원본 해시, 코드 커밋, fold별 모델/학습 곡선, 전체 설정의 실행별 동결 기록은 부족하다. 이번 감사에서의 재추론 일치와 전 학습 과정의 재현 가능성은 서로 다른 확인 범위다.
- `DATA_SOURCES.md`는 루트 설계서가 폴더 밖에 있다고 설명하지만 현재는 프로젝트 루트에 있다. 루트 설계서가 요구한 다운로드일·사용조건 등 출처 항목도 보완할 수 있다.

## 5. 권장 진행 순서

| 순서 | 작업 | 완료 판단 기준 |
|---|---|---|
| 1 | 동일 시각 충돌·Total 정책·실행 시각 확정 | 원본 키, 동률 정책, 목표/입력 단위와 마감 시각이 문서화됨 |
| 2 | 시험 기반 부품별 선택 제거 | 모델 선택과 연관 후보 계산이 과거 학습/검증 안에서만 실행됨 |

우선순위 1~3은 모델을 더 오래 학습시키기 전에 해결해야 한다. 현재 증거로 말할 수 있는 결론은 **“학습 및 재추론은 정상 작동하며, 검사한 고정 후보 중 CV에서는 이동평균이 ML 후보를 앞섰다. 하지만 누락된 최근값 기준, 원본 충돌 정책, 시험 기반 선택 때문에 최종 운영 선택은 재검토가 필요하다”**이다.

검증 원칙 참고: [scikit-learn 데이터 누수 지침](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage), [모델 선택과 교차검증](https://scikit-learn.org/stable/modules/cross_validation.html). 시험 데이터로 모델의 선택 사항을 결정하지 않고, 변환과 변수 선택을 학습 데이터 안에서 수행해야 한다는 원칙을 적용했다.
