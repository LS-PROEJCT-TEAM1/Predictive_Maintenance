# VMI 발주량 예측 프로젝트 분석 계획

## 1. 프로젝트 목적

본 프로젝트의 목적은 **VMI(Vendor Managed Inventory) 환경에서 고객사(모기업)가 제공하는 계획 발주량과 실제 발주량의 차이를 AI로 보정하여 미래 실제 발주량을 예측**하는 것이다.

현재 협력기업(공급사)은 고객사가 제공하는 당일 발주량과 향후 계획 발주량을 바탕으로 생산 및 재고 계획을 수립한다. 그러나 계획 발주량은 시간이 지나며 변경될 수 있기 때문에 다음과 같은 문제가 발생한다.

- 계획 발주량보다 실제 발주량이 많을 경우: 재고 부족, 긴급 생산, 납기 지연 위험
- 계획 발주량보다 실제 발주량이 적을 경우: 과잉 생산, 재고 부담, 보관 비용 증가
- 기존에는 숙련 작업자 또는 담당자의 경험에 의존하여 계획 발주량을 보정하는 경우가 많음

따라서 본 프로젝트에서는 머신러닝 및 딥러닝 모델을 활용하여 고객사의 계획 발주량을 보정하고, **보다 정확한 미래 실제 발주량을 예측하는 모델**을 구축한다.

## 3. 주요 컬럼 및 분석 대상

### 3.1 식별 및 시간 컬럼

- `Part Number`
  - 부품 식별자
  - 총 117개 부품
- `CRET_TIME`
  - 해당 발주 및 계획 발주 정보가 기록된 시간

### 3.2 목표 변수(Target)

기본 목표 변수는 다음과 같이 설정한다.

- `D일 투입예정 수량(D일계획)`

의미:
- 실제 해당 날짜에 투입되는 발주 수량
- 미래 시점에서 예측해야 할 실제 발주량

### 3.3 주요 입력 변수 후보

가이드북에서 미래 실제 발주량과 상관관계가 높은 변수로 확인된 계획 발주량을 중심으로 사용한다.

- `D+3일 투입예정 수량(Total)`
- `D+4일 투입예정 수량(Total)`
- `D+5일 투입예정 수량`

필요 시 추가 후보:

- `D+1일 투입예정 수량(Total)`
- `D+2일 투입예정 수량(Total)`
- `D+6일 ~ D+12일 투입예정 수량`
- 당일 시간대별 발주 수량
- 부품별 과거 실제 발주량

## 4. 핵심 분석 질문

본 프로젝트에서 답해야 할 핵심 질문은 다음과 같다.

> 고객사가 3~5일 전에 제공한 계획 발주량과 과거 실제 발주 패턴을 이용하여, 3일 뒤 실제 발주량을 얼마나 정확하게 예측할 수 있는가?

추가 질문:

1. 기존 고객사 계획 발주량을 그대로 사용하는 것보다 AI 모델이 실제 발주량을 더 정확하게 예측하는가?
2. LightGBM, XGBoost, LSTM 중 어떤 모델이 이 데이터에서 가장 좋은 성능을 보이는가?
3. 모델별로 과대예측 또는 과소예측 경향이 있는가?
4. 예측 오차를 활용하여 재고 부족 또는 과잉 재고 위험을 정량적으로 표현할 수 있는가?

## 5. 데이터 전처리 계획

### 5.1 기본 품질 검사

다음 항목을 확인한다.

- 결측치
- 중복 데이터
- 날짜 형식
- 부품별 데이터 수
- 이상치
- 0 발주량 비율
- 부품별 기간 누락 여부

### 5.2 시간 기준 일 단위 정제

가이드북에서는 하루에 동일 부품의 발주 로그가 여러 번 존재하는 경우, 해당 날짜의 가장 마지막 로그가 그날의 최종 발주 정보를 가진다고 본다.

따라서:

1. `CRET_TIME`을 datetime으로 변환
2. `Part Number + 날짜` 기준 그룹화
3. 각 날짜의 마지막 로그만 사용

이를 통해 부품별 일 단위 시계열을 구축한다.

### 5.3 데이터 누수 방지

미래 예측 시점에서 알 수 없는 정보는 입력값으로 사용하지 않는다.

예:
- 예측하려는 날짜 이후에 수정된 계획 발주량
- 실제 미래 발주량에서 계산된 값

사용 가능한 정보만 시점 기준으로 정렬한다.

## 6. Feature Engineering 계획

머신러닝 모델 성능 향상을 위해 다음 파생변수를 생성한다.

### 6.1 계획 발주량 관련 변수

- D+3 계획량
- D+4 계획량
- D+5 계획량
- 최근 계획량 평균
- 계획량 최대값
- 계획량 최소값

### 6.2 계획 수정량 관련 변수

예:

- 계획 변경량 = 최신 계획량 - 이전 계획량
- 계획 변경률 = (최신 계획량 - 이전 계획량) / 이전 계획량
- 최근 2일 계획 증감
- 최근 3일 계획 증감 추세

### 6.3 실제 발주량 Lag 변수

- lag_1: 1일 전 실제 발주량
- lag_2: 2일 전 실제 발주량
- lag_3: 3일 전 실제 발주량
- lag_7: 7일 전 실제 발주량

### 6.4 Rolling 통계 변수

- 최근 3일 평균 발주량
- 최근 7일 평균 발주량
- 최근 3일 표준편차
- 최근 7일 표준편차

### 6.5 날짜 변수

- 요일
- 주말 여부
- 월
- 주차

### 6.6 부품 변수

- `Part Number`

LightGBM/XGBoost에서는 부품 정보를 범주형 인코딩 또는 적절한 방식으로 변환하여 활용한다.

## 7. 모델 구성

본 프로젝트에서는 총 3개의 주요 모델을 학습하고 동일 조건에서 비교한다.

### 7.1 LightGBM

역할:
- 주력 머신러닝 모델 후보

선정 이유:
- 비교적 적은 데이터에서도 성능이 좋은 편
- 비선형 관계 학습 가능
- 다수의 파생변수 활용에 적합
- 학습 속도가 빠름
- Feature Importance 및 SHAP 해석 가능

입력:
- 계획 발주량
- lag 변수
- rolling 변수
- 계획 변경량
- 날짜 변수
- Part Number

출력:
- 미래 실제 발주량

---

### 7.2 XGBoost

역할:
- LightGBM과 비교할 머신러닝 모델

선정 이유:
- 정형 데이터 기반 회귀 문제에서 높은 성능
- 작은~중간 규모 데이터에 안정적
- 과적합 제어 기능이 강함
- LightGBM과 비교를 통해 모델 선택의 신뢰성을 높일 수 있음

입력:
- LightGBM과 동일한 Feature Set

출력:
- 미래 실제 발주량

---

### 7.3 LSTM

역할:
- 딥러닝 시계열 비교 모델

선정 이유:
- 가이드북에서 사용한 기준 AI 모델
- 시계열 순서를 직접 학습 가능
- 계획 발주량의 시간 흐름 및 장기 의존성 학습 가능

주의점:
- 실제 분석 기간이 약 50일로 짧아 부품별 시계열 데이터가 매우 적음
- 딥러닝 특성상 데이터 부족으로 과적합 가능성이 큼
- 따라서 최종 주력 모델로 미리 결정하지 않고 비교 대상으로 사용

입력 예시:
- 과거 3일 또는 5일 시계열
- 각 시점의 실제 발주량
- D+3, D+4, D+5 계획 발주량

출력:
- 3일 뒤 실제 발주량

## 8. Baseline 모델

### Baseline 1. 고객사 계획 발주량

예:

목적:

> AI 모델이 기존 고객사 계획 발주량보다 실제 발주량을 얼마나 더 정확하게 예측하는가?

### Baseline 2. 단순 이동평균

예:

- 최근 3일 실제 발주량 평균
- 최근 7일 실제 발주량 평균

필요 시 보조 기준으로 사용한다.

## 9. 학습 및 검증 전략

데이터는 시계열이므로 랜덤 셔플 방식의 train/test split을 사용하지 않는다.

### 9.1 시간 순서 분할

예:

- Train: 초기 60~70%
- Validation: 다음 10~20%
- Test: 마지막 20%

### 9.2 Walk-Forward Validation

데이터 기간이 짧기 때문에 단 한 번의 Test 결과만으로 모델을 판단하지 않는다.

예:

1. 앞 기간 학습 → 다음 기간 검증
2. 학습 구간 확장
3. 다음 기간 다시 검증
4. 반복

이를 통해 다음을 확인한다.

- 평균 성능
- 기간별 성능 변동성
- 모델 안정성

가능하면 각 모델의 지표를 다음과 같이 제시한다.

- 평균 MAE ± 표준편차
- 평균 RMSE ± 표준편차
- 평균 WAPE ± 표준편차

## 10. 모델 성능 평가 지표

모든 모델은 동일한 Test 구간에서 다음 지표를 계산한다.

### 10.1 MAE

Mean Absolute Error

공식:

MAE = 평균(|실제값 - 예측값|)

의미:

- 평균적으로 실제 발주량에서 몇 개 정도 틀리는지 표현
- 가장 직관적인 핵심 평가 지표

해석 예:

- MAE = 5.2
- 평균적으로 약 5.2개의 발주 수량 오차가 발생

목표:
- 낮을수록 좋음

---

### 10.2 RMSE

Root Mean Squared Error

공식:

RMSE = sqrt(평균((실제값 - 예측값)^2))

의미:

- 큰 예측 오차에 더 큰 패널티를 부여
- 대규모 재고 부족 또는 과잉 생산 위험을 확인하기 좋음

목표:
- 낮을수록 좋음

---

### 10.3 WAPE

Weighted Absolute Percentage Error

공식:

WAPE = sum(|실제값 - 예측값|) / sum(실제값) × 100

의미:

- 전체 발주량 대비 예측 오차 비율
- 부품별 발주 규모가 서로 다를 때 비교하기 좋음

MAPE 대신 WAPE를 사용하는 이유:

- 데이터에 실제 발주량이 0인 경우가 존재할 수 있음
- MAPE는 실제값이 0일 때 계산 문제가 발생
- WAPE는 전체 수량 기준으로 비교 가능

목표:
- 낮을수록 좋음

---

### 10.4 Forecast Bias

공식:

Forecast Bias = 평균(예측값 - 실제값)

의미:

- 모델이 지속적으로 과대예측 또는 과소예측하는지 확인

해석:

- Bias > 0: 과대예측 경향 → 과잉재고 위험
- Bias < 0: 과소예측 경향 → 재고부족 위험
- Bias ≈ 0: 한쪽으로 치우치지 않음

목표:
- 0에 가까울수록 좋음

---

### 10.5 R²

Coefficient of Determination

의미:

- 실제 발주량의 변동을 모델이 얼마나 설명하는지 나타냄

해석:

- 1에 가까울수록 설명력이 높음
- 0에 가까우면 단순 평균 예측과 유사
- 음수이면 단순 평균보다도 예측력이 낮을 수 있음

목표:
- 높을수록 좋음

## 11. 최종 성능 비교표

최종 보고서 및 Dash에서는 다음 형태로 비교한다.

|---|---:|---:|---:|---:|---:|
| D+3 고객사 계획량 Baseline | 계산 | 계산 | 계산 | 계산 | 계산 |
| Moving Average Baseline | 계산 | 계산 | 계산 | 계산 | 계산 |

| LightGBM | 계산 | 계산 | 계산 | 계산 | 계산 |
| LSTM | 계산 | 계산 | 계산 | 계산 | 계산 |

추가 지표:

- Baseline 대비 MAE 개선율
- Baseline 대비 RMSE 개선율
- Baseline 대비 WAPE 개선율

예:

MAE 개선율 = (Baseline MAE - Model MAE) / Baseline MAE × 100

## 12. 최종 모델 선정 기준

최종 모델은 단일 지표가 아니라 다음 기준을 종합해 선정한다.

우선순위:

1. MAE
2. RMSE
3. WAPE
4. Forecast Bias
5. R²
6. Walk-forward 평균 성능과 안정성
7. 해석 가능성
8. 학습 및 추론 속도

예:

- LightGBM이 MAE, RMSE, WAPE에서 가장 우수하고 Bias도 0에 가까우면 최종 모델로 선정
- LSTM이 일부 지표에서 우수하더라도 성능 변동성이 크면 운영 모델 선정 시 주의
- XGBoost가 LightGBM과 성능이 유사하지만 안정성이 더 좋다면 최종 후보가 될 수 있음

## 13. 최종 모델 이후 재고 의사결정 연결

발주량 예측 자체에서 끝내지 않고 재고 의사결정으로 연결한다.

### 13.1 예측 발주량

예:

- 3일 뒤 예상 발주량: 120개

### 13.2 현재 재고

예:

- 현재 재고: 90개

### 13.3 부족 예상량

부족 예상량 = 예측 발주량 - 현재 재고

예:

- 120 - 90 = 30개 부족 예상

### 13.4 재고 위험 상태

예:

- 정상
- 재고 부족 주의
- 재고 부족 위험
- 과잉 재고 주의
- 과잉 재고 위험

### 13.5 권장 생산량

예:

권장 생산량 = 예측 발주량 + 안전재고 - 현재 재고

안전재고는 모델의 예측 오차(MAE, RMSE 등)를 기반으로 별도 정책을 설계한다.
