# 공급망 예측 대시보드 — 화면 설계 README

BatteryFlow AI Control Tower 중 **공급망 예측(김유빈 담당)** 모듈의 UI 설계 의도를 정리한 문서입니다.

- 설계 파일: `공급망 예측 대시보드 v2.dc.html` (최종, 팀 공통 틀 + 팔레트 적용)
- 이전 버전: `공급망 예측 대시보드 와이어프레임.dc.html` (요구사항 정리 + 흑백 와이어프레임)

---

## 1. 목적

> 고객사가 준 계획 발주량(D+1~D+12)과 과거 실제 발주 이력을 이용해 **3일 뒤(D+3) 실제 발주량을 예측**하고, 담당자가 이를 보고 **확보 수량을 결정**하도록 돕는다.

대시보드가 답해야 하는 질문은 세 가지입니다.

1. **오늘 어떤 부품을 봐야 하나?** → 계획과 AI 예측의 차이가 큰 부품
2. **그 부품은 3일 뒤 실제로 얼마나 발주될까?** → 예측값과 오차 범위
3. **그래서 얼마나 더 확보해야 하나?** → 재고·입고 조건을 넣은 시나리오

그 밖의 화면(모델 성능, 데이터 탐색·관리, 리포트)은 이 판단을 **믿을 수 있는 근거**와 **평가 요구사항**을 채우려고 만들었습니다.

## 3. 정보 구조 (IA)

```
사이드바 (팀 공통)            헤더 가로 탭 (공급망 예측)
├ 통합 현황                  ├ 발주 현황      ← 기본 탭
├ 공급망 예측  ●             ├ 부품별 예측    ← 핵심
├ 품질 보증                  ├ 재고 시나리오
└ 예지 보전                  ├ 모델 성능
                             ├ 데이터 탐색
                             ├ 데이터 관리
                             └ 리포트
```

**탭 순서의 이유**
- 앞쪽 3개(발주 현황 → 부품별 예측 → 재고 시나리오)는 담당자가 매일 하는 **업무 순서**입니다.
- 뒤쪽 4개는 **근거 확인·데이터 준비·산출물** 화면입니다. 자주 쓰진 않지만 평가 항목을 직접 채웁니다.
- 데이터 탐색과 데이터 관리를 나눈 건 **팀 레퍼런스(예지 보전)** 구성과 맞추기 위해서입니다. 모듈이 달라도 같은 방식으로 조작할 수 있습니다.

## 4. 사용자 흐름

```
발주 현황 ──(편차 큰 부품 클릭)──▶ 부품별 예측 ──▶ 재고 시나리오 ──▶ 리포트
                                    │  ▲
                        "믿어도 되나?" ▼  │
                         모델 성능 · 데이터 탐색 · 데이터 관리
```

전체 부품을 한눈에 보고 → 한 부품을 자세히 보고 → 수량을 결정하고 → 저장합니다. 판단이 흔들리면 성능·데이터 화면으로 갔다가 다시 부품별 예측으로 돌아옵니다.

## 5. 화면별 설계 의도

### 2a. 발주 현황 — "오늘 무엇을 볼까"

| 구성 | 만든 이유 | 이렇게 구성한 이유 |
|---|---|---|
| 전역 필터 (부품·기간·상태·모델) | 설계서 "필터" 필수 | 모든 탭의 KPI·그래프·표가 **같은 조건으로 함께 바뀌어야** 함 (평가: Dash 통합) |
| KPI 4개 | 상황을 먼저 숫자로 파악 | 첫 카드(AI 예측 합계)만 검정 배경으로 강조. 바로 옆에 계획 합계를 둬서 **차이가 바로 보이게** 함 |
| 일별 발주량 합계 차트 | 계획과 실제가 벌어지는 구조를 보여줌 | 실제(검정 실선), 계획(회색 점선), AI(청록 굵은 선). **주말 음영**을 넣어 "주말엔 계획이 0이어도 실제 발주는 있다"는 패턴이 드러나게 함 |
| 부품별 D+3 편차 순위 표 | 117개 부품을 다 볼 수 없으므로 우선순위가 필요 | \|AI − 계획\| 큰 순서로 정렬, 상태 칩(▲부족/▼과잉 × 위험/주의), 행을 누르면 부품별 예측으로 이동 |

### 2b. 부품별 예측 — 핵심 화면

| 구성 | 만든 이유 | 이렇게 구성한 이유 |
|---|---|---|
| 예측값 카드 (417 ± 57) | 담당자가 가장 궁금한 답 | **답을 먼저, 가장 크게.** 한 숫자만 있으면 과신하게 되므로 오차 범위(±MAE)를 같이 표시 |
| 계획 · 차이 · 테스트 MAE | 예측을 믿을지 판단할 근거 | 이 부품의 과거 오차(AI 57 vs 계획 231)를 보여줘서 "이 부품은 AI가 더 잘 맞았다"를 알게 함 |
| 발주 이력 → D+3 예측 차트 | 설계서 "실제값·예측값" 필수 | 과거와 미래(회색 음영)를 **한 축**에 둬서 흐름이 이어지게 함. 오차 범위는 연청록 띠 |
| 계획 변경 추이 (D+5→D+4→D+3) | VMI 문제의 본질은 계획이 계속 바뀐다는 것 | 분석계획서의 "계획 변경량" 피처를 그대로 그림. 같은 날짜의 계획이 시간에 따라 어떻게 바뀌었는지 보여줌 |
| 오차 분포 | 과대·과소 경향 확인 (분석계획서 Bias) | 0을 가운데 두고 왼쪽 과소, 오른쪽 과대 |
| 모델별 예측 | 모델마다 결과가 얼마나 다른지 | 1위 모델 행만 강조하고 계획값은 회색 기준선으로 둠 |
| AI Copilot 패널 | 기획서의 담당 기능 | 선택한 부품·날짜를 자동으로 넘겨받음. 답변마다 **수치 파일 + 가이드북 출처**를 표시 (기획서: 근거가 없는 답변 방지) |

### 2c. 재고 시나리오 (What-If) — "얼마나 확보할까"

| 구성 | 만든 이유 | 이렇게 구성한 이유 |
|---|---|---|
| 입력 (현재 재고·입고 예정·안전재고 계수) | 기획서 4.2 What-If | 원본에 재고·입고 데이터가 없으므로 **"사용자 입력" 배지**로 분명히 구분. 안전재고는 모델 MAE × k |
| A 계획 기준 / B AI 기준 비교 | "AI를 쓰면 무엇이 달라지나"를 보여줌 | 같은 조건에서 두 방식을 나란히 계산. AI 카드만 청록 강조 |
| 재고 위험 판정 | 분석계획서 13장 (위험 5단계) | 확보 가능량(막대)과 필요량(청록 선·점선)을 한 줄에 겹쳐서 **부족·과잉이 눈으로 보이게** 함 |
| 저장 · 일괄 계산 · CSV | 기획서 "CSV 저장" | 한 부품 → 전체 부품으로 넓혀서 계산할 수 있게 함 |

> 설계 파일에서 실제로 입력하면 결과가 다시 계산됩니다. 계산식: `추가 확보 = 예측 + 안전재고 − (재고 + 입고)`

### 2d. 모델 성능 — "믿어도 되나"

| 구성 | 만든 이유 | 이렇게 구성한 이유 |
|---|---|---|
| 최종 모델 + 개선율 KPI | 평가 "기준 모델 비교" 15점 | 핵심 메시지 "계획 대비 MAE −33%"를 맨 위에 둠. 1위가 **단순 3일 이동평균**이라는 결과도 숨기지 않음 |
| 공통 테스트 성능표 | 분석계획서 11장 비교표 | metrics_test.csv 실제 값. MAE는 막대, Bias는 **0 기준 좌우 막대**라 과소·과대가 바로 보임 |
| Walk-Forward 폴드별 MAE | 50일 데이터라 테스트 한 번으로는 부족 | 폴드별로 오차가 얼마나 흔들리는지로 **안정성**을 보여줌 (자리만 잡아둠) |
| 검증 조건 | 평가 "시간 분할·누수 방지" | 학습 70 / 검증 10 / 테스트 20 비율을 팔레트 3단계 색 막대로 표시 |

### 2e. 데이터 탐색 — EDA

| 구성 | 만든 이유 | 이렇게 구성한 이유 |
|---|---|---|
| 요일별 발주량 박스플롯 + 통계표 | 주말 패턴 확인 | 팀 레퍼런스의 "박스플롯 + count/mean/std…" 구성을 그대로 사용해 모듈 간 일관성 유지 |
| D+k 계획 ↔ 실제 상관 히트맵 | 가이드북의 변수 선택 근거 | 팔레트 5단계(흰색 → 진청록)를 농도 단계로 사용. 레퍼런스의 변수 상관관계 카드와 같은 형태 |
| 부품별 발주 규모 Top 7 | 발주량이 큰 부품이 오차를 주도함 | 예측 화면의 부품(Part 106)만 청록으로 표시해 화면끼리 연결 |
| 0 값 비율 | 계획 0 행이 58%, 실제 0 행이 21% | "계획을 그대로 쓰면 과소예측된다"(Bias −34.6)를 데이터로 설명 |
