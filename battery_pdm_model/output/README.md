| 2 | 결측치·중복 확인 후 제거 | 모든 파일에서 결측 0건, 중복 0건 |

## 5. 모델 구성 – Feature / Target / 회귀·분류

### Feature와 Target

| 구분 | 컬럼 | 설명 |
|---|---|---|
| **Feature (공정 조건)** | `PageNo` | 용접 포인트 순번 (1~39) |
| | `Speed` | 용접 속도 설정 (mm/s) |
| | `Length` | 용접 길이 설정 (mm) |
| | `SetPower` | 용접 출력 설정 (%) |
| | `GateOnTime` | 용접 게이트 오픈 시간 |
| **회귀 Target** | `RealPower` | 실제 용접 출력 (W) |
| **분류 Target (평가용 정답)** | `label` | 0 = 정상, 1 = 이상 (NG 라벨 파일) |

- `RealPower`의 이전 값(lag)은 Feature로 쓰지 않았다. 04_NG처럼 이상이 길게 이어지면 lag가 이상값을 따라가서 예측도 같이 떨어지고, 그 결과 이상을 놓치게 된다.
- `WorkingTime`은 정렬, 분할, 조회에만 쓰고 Feature로는 쓰지 않았다. 트리 모델은 학습 기간 밖으로 외삽하지 못하기 때문이다.

### 회귀 모델: LightGBM Regressor

발주량 예측 모델의 LightGBM 설정을 그대로 가져왔다.

- `objective="regression_l1"` (MAE 손실), `learning_rate=0.03`, `num_leaves=31`, `subsample·colsample=0.85`, `reg_alpha=0.2`, `reg_lambda=5.0`
- **학습 절차**
  1. 시간 순 앞 80%로 학습하고 뒤 20%로 검증하며 early stopping(60)을 적용한다. 결과는 best_iteration = 470이다.
  2. 시간 블록 5-fold로 out-of-fold(OOF) 예측을 만든다. 학습에 쓰지 않은 기간의 잔차이므로 드리프트까지 포함한 **정상 변동폭**을 담는다.
  3. 전체 학습 데이터로 최종 모델을 재학습한다.

### 분류(이상 판정): 잔차 Z-score

```
잔차     = 실제 RealPower − LightGBM 예측값
Z-score = (잔차 − 조건별 정상 잔차 중앙값) / 조건별 robust 표준편차(1.4826 × MAD)
|Z| ≥ 4.0 → 이상(1), 아니면 정상(0)        ← 가이드북 threshold 4.0
```

- 기준값은 **테스트가 아니라 학습(정상) 데이터의 OOF 잔차**로 고정한다 (데이터 누수 방지).
  - 38%: 중앙값 0.0, σ = 3.0W
  - 82%: 중앙값 −0.3, σ = 7.9W
  - 83%: 중앙값 −0.7, σ = 8.5W
- 평균·표준편차 대신 중앙값·MAD를 쓴 이유: 드문 레시피 때문에 생긴 예측 오차 수백 행이 82/83%의 표준편차를 65W까지 키워 이상을 놓치게 만들었기 때문이다.
- 학습에 없던 SetPower(예: 35%)는 가장 가까운 조건(38%)의 기준을 쓰고, 점검 사유에 "학습에 없는 출력 설정값 확인"을 덧붙인다.
- 대시보드용 `anomaly_prob`(이상 점수)는 `1 / (1 + exp(−2·(|Z| − 4)))`로 계산한다. |Z|가 4일 때 0.5이고, 커질수록 1에 가까워진다. 참고용 점수이며 통계적 확률은 아니다.

## 6. 결과

### 회귀 성능 (RealPower 예측)

| 구간 | MAE | RMSE | R² |
|---|---|---|---|
| 검증 (시간 분할, 2022-06-22 ~ 07-29) | 11.06 | 12.21 | 0.9994 |
| 01_OK | 11.16 | 12.12 | 0.9994 |
| 02_OK | 12.43 | 13.45 | 0.9992 |
| 03_NG 정상행 | 13.33 | 14.41 | 0.9991 |
| 04_NG 정상행 | 35.26 | 164.69 | 0.8895 |

가이드북의 허용 한도는 2000W의 3~4%, 즉 60~80W이고, 정확도 기준은 1%인 20W다. 정상 구간 MAE 11~13W는 이 기준 안에 들어온다.

### 이상 탐지 성능 (|Z| ≥ 4)

| 파일 | Accuracy | Precision | Recall | F1 | 오경보율 | TN / FP / FN / TP |
|---|---|---|---|---|---|---|
| 01_OK | 1.0000 | – | – | – | 0.00 | 1950 / 0 / 0 / 0 |
| 02_OK | 1.0000 | – | – | – | 0.00 | 1872 / 0 / 0 / 0 |
| 03_NG | **1.0000** | **1.0000** | **1.0000** | **1.0000** | 0.00 | 1034 / 0 / 0 / 19 |
| 04_NG | 0.9858 | 0.9820 | **1.0000** | 0.9909 | 0.064 | 73 / 5 / 0 / 273 |
| **전체** | **0.9990** | **0.9832** | **1.0000** | **0.9915** | 0.001 | 4929 / 5 / 0 / 292 |

**가이드북 결과와 비교**

| 파일 | 가이드북 | LightGBM |
|---|---|---|
| 03_NG | N-HiTS F1 0.8947 | F1 1.0 |
| 04_NG | 통계 Z-score F1 1.0 | F1 0.991 |

**하나의 모델로 두 가지 이상 유형(단발성·연속)을 모두 탐지**하며, 이상을 놓친 경우(FN)는 0건이다.

04_NG의 오경보 5건은 다음과 같다.

- 3건: 82% 조건에서 출력이 +30W 높았다 (|Z| 4.1~4.3). 1월 수준의 높은 출력이라 경계값 근처에서 걸렸다.
- 2건: 설정은 83%인데 출력은 693W, 설정은 38%인데 출력은 1717W였다. 설정과 출력이 한 행씩 어긋난 것으로, 라벨은 정상이지만 **실제로 확인이 필요한 불일치**다.

### 변수 중요도 (gain)

Speed > Length > PageNo > SetPower > GateOnTime

- 파일 이름이 `lightgbm.py`라서 `import lightgbm`이 자기 자신을 불러오는 문제(circular import)가 있다. 코드 안에서 이 폴더를 import 경로에서 빼는 방식으로 처리했다. 나중에 파일 이름을 `lightgbm_model.py` 같은 이름으로 바꾸는 것을 권장한다.
- 실행 시간은 약 1분 이내다 (5-fold 포함).

## 9. 핵심 결론 · 한계 · 개선 제안

**핵심 결론**

- 공정 조건만으로 RealPower를 R² 0.999 수준으로 예측할 수 있다. 예측에서 크게 벗어난 잔차를 이상으로 판정하는 방식으로 **단발성·연속 이상을 모두 Recall 1.0으로 탐지**했다.
- 학습 기간 동안 **월별 출력 저하(최대 약 22W)**가 확인돼, 이상이 나기 전의 열화 징후로 활용할 수 있다.

**한계**

- 라벨이 있는 이상 데이터가 2개 파일, 292행뿐이라 임계값(4.0)이 일반화된다고 보장하기 어렵다.
- 모델이 시간 추세를 반영하지 못해 출력이 높았던 초기 수준(1월)이 오면 경계값 근처에서 오경보가 날 수 있다 (04_NG 3건).
- 이상 점수(`anomaly_prob`)는 |Z|를 변환한 참고용 점수이며, 실제 고장 확률로 보정된 값이 아니다.
- 설계서 8번 평가 기준의 **K-Means 기반 비지도 이상 탐지**는 이번 코드에 포함하지 않았다.

**개선 제안**

1. 최근 N개 모듈 기준으로 잔차 기준을 갱신하는 **이동 기준선(rolling baseline)**을 적용해 드리프트에 대응한다.
2. Decision Tree, Random Forest, Isolation Forest와 같은 표로 성능을 비교하고 **K-Means 군집 기반 이상 탐지**를 추가해 설계서 요구사항을 채운다.
3. 모듈(39포인트) 단위 집계 지표(평균 잔차, 이상 포인트 수)를 만들어 **모듈 단위 양품/불량 판정**으로 확장한다.
4. 실제 정비·알람 이력을 연동해 점검 사유와 우선순위 규칙을 검증한다.
