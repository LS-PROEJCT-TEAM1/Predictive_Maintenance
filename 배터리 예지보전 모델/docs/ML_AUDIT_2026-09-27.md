# 예지보전 ML 학습·검증 감사

감사일: 2026-09-27 / 대상: `track-b-final-v2`

## 1. 종합 판정

**기존 데이터의 현재 이상 감지 실험으로서는 학습·예측·성적의 일관성이 확인된다. 다만 운영 입력 처리와 검증 근거에 보완이 필요하며, 새로운 현장 고장에 대한 일반화나 고장 사전 예측까지 검증된 상태는 아니다.**

저장 모델 6개를 원본 데이터에 다시 적용한 결과, validation·locked test의 18,954개 행×모델 판정이 저장 결과와 모두 일치했다. 공식 로컬 시드의 5,226행×6개 모델 점수·판정도 모두 재현했다. 성적 조작이나 현재 코드에서 시험 라벨을 직접 학습에 사용하는 경로는 확인되지 않았다. 그러나 과거에도 사용한 시험 파일을 새 외부 시험처럼 해석할 수는 없다.

가장 먼저 고쳐야 할 구현 오류는 **결측·무한대 RealPower나 존재하지 않는 PageNo가 정상 판정으로 바뀌는 입력 처리**다. 그다음으로 사이클 단위 운영 평가, 적은 이상 사례에 대한 검증, 시간 이상 처리, 모델 선택 설명의 정합성을 보완해야 한다.

이번 작업은 감사만 수행했다. 학습 코드·모델·raw 데이터·공식 시드·화면을 수정하지 않았으며 재학습, Firestore 업로드, GitHub 반영을 수행하지 않았다. 품질 보증 모델은 감사 대상에서 제외했다.

전체 프로토콜은 시간상 미래에 해당하는 모든 시험을 평가하는 구조는 아니다. 정상 기준 학습 95,004행 중 89,895행은 02_OK 시험일인 2월 11일 이후 자료다. 현재 결과는 **파일 분리 기반의 과거 데이터 평가**로 해석해야 한다. 시험 라벨 누수와는 구분되는 시간적 적용 가능성 문제다.

### 정상 기준 정제와 중복

Training_Data의 cycle_694는 RealPower 39행이 모두 0이며 정상 기준 학습/보정에서 제외된다. NG04에도 0 출력 39행이 있으나 시험 데이터에서는 유지된다. 이 처리는 출력 정지 상태가 정상 출력 기준을 왜곡하지 않게 한다. 다만 현장에서는 정지·센서 오류·실제 공정 이상을 구분할 규칙이 필요하다. 코드의 제외 조건은 '하나라도 0'이므로 문서의 '전체 0'보다 넓으며, 현재 파일에서는 같은 1개 사이클이 제외되지만 새 파일에서는 결과가 달라질 수 있다.

시간을 포함한 전체 raw 행은 분할 간 겹치지 않는다. 시간을 제외한 39행 신호가 동일한 사이클은 정상 fit→calibration 9개, calibration→개발 validation 4개가 확인됐다. 개발 train/validation과 locked test 사이에는 같은 완전 사이클 신호가 없었다. 반복·양자화된 공정 신호일 수 있으므로 이 사실만으로 원본 복제나 부정 누수라고 단정할 수 없다. 향후 분할 민감도 점검에서는 동일 신호 그룹도 추적하는 편이 좋다.

validation+locked test 18,954개 행×모델의 판정 불일치는 0이다. CSV 저장 점수와 재추론 점수의 최대 차이는 약 2.27e-13으로 부동소수점 정밀도 범위다.

최종 모델 RobustPhaseZ는 이 시험에서 이상 273행을 모두 탐지했고 정상 1,950행 중 3행에서 오경보를 냈다. 다만 이상 273행은 독립 고장 273건이 아니라 **NG04의 단일 연속 사건**이다. RandomForest와 IsolationForest도 이 사건에 한 번 이상 반응하여 이벤트 Recall은 1.0이지만, 행 Recall은 각각 61.54%, 6.23%다. 따라서 이벤트 Recall 100%만을 성공 기준으로 강조하면 탐지 품질 차이를 숨길 수 있다. 기존 보고서가 행 Recall을 함께 제시한 점은 적절하다.

### 사이클 단위 추가 진단

감사에서 '39행 중 실제 이상이 하나라도 있으면 이상 사이클, 예측 경보가 하나라도 있으면 경보 사이클'로 단순 집계했다. 기존에 학습·최적화한 별도 사이클 정책은 아니며, 행 지표를 운영 결과로 곧바로 해석할 수 없음을 확인하기 위한 진단이다.

RobustPhaseZ의 locked test 57사이클 결과:

- 실제 이상 7사이클 중 탐지 7, 미탐 0.
- 실제 정상 50사이클 중 오경보 1, 정상 판정 49.
- Precision **87.5%**, Recall **100%**, F1 **0.9333**, 정상 사이클 FPR **2%**.
- 7개 이상 사이클 역시 같은 장기 사건에 속하므로 독립 고장 7건으로 세면 안 된다.

현재 행 FPR 0.1538%와 사이클 FPR 2%는 서로 다른 지표다. 기존 '정상 행 FPR≤1%' 기준을 실패했다고 바꾸어 말할 수는 없다. 대신 점검을 사이클 단위로 수행한다면 사이클 단위 승인 기준을 별도로 정해야 한다.

### 현재 시스템과 연결

공식 로컬 시드의 예지보전 문서는 99개이며 측정값은 4개 시험 파일 총 5,226행이다. 원본 RealPower·라벨·행 번호와 일치하고, 31,356개 행×모델 점수 및 판정도 저장 모델 재추론과 일치했다.

실제 기본 화면 판정은 `LogisticCurrent OR RobustPhaseZ`다. locked test에서는 이 조합의 판정이 RobustPhaseZ 단독과 2,223행 모두 같아 기존 성능표와 수치 차이가 없다. 그러나 다른 모델 조합을 선택하면 다른 운영 규칙이 된다. 단일 모델 평가와 조합 평가를 명확히 구분하고, 운영할 조합을 별도 버전으로 기록해야 한다. 근거: 루트 `backend/data.py:96`, `backend/data.py:110`, 모델 디렉터리 `app.py:73`.

## 6. 보완사항: 우선순위와 근거

### P1 — 잘못된 센서 입력을 '정상'으로 통과시킴

근거: `src/track_b_final_v2.py:113`, `:232`, `:277`; `src/predict_track_b.py`의 read_signal→add_identity→score 경로.

필수 열 존재와 날짜 변환만 확인하고 numeric finite, PageNo 범위, 완전 사이클, 시간 증가를 추론 진입점에서 검증하지 않는다. 특징 계산에서 NaN/Inf를 모두 0으로 바꾸면서 이상도 PhaseAbsZ까지 0이 된다.

실제 정상 39행 사본을 변형한 결과:

| 변형 | 입력 허용 | 기본 모델 결과 |
|---|---|---|
| RealPower 전부 NaN | 허용 | 39행 전부 정상, 점수 0 |
| RealPower 전부 +Inf | 허용 | 39행 전부 정상, 점수 0 |
| PageNo 전부 999 | 허용 | 39행 전부 정상, 점수 0 |
| RealPower 전부 음수 | 허용 | 39행 이상 판정; 유효하지 않은 물리 입력이라는 별도 상태 없음 |
| WorkingTime 역순 | 허용 | 판정 가능, 시간 오류로 중단하지 않음 |

NaN 사례는 실제 `predict_track_b.py` 실행으로도 `rows=39 anomalies=0`을 확인했다. 현재 제공 raw가 깨졌다는 의미가 아니라 **새 입력에서 발생하는 운영 오류**다.

조치: 입력 형식·유한값·PageNo·사이클·시간을 검사하고, 입력 오류와 공정 이상을 별도 상태로 반환한다. 결측 센서값을 정상 점수로 대체하지 않는다. 허용 범위는 raw 관찰 범위와 실제 설비의 물리 제약을 구분하여 설정한다.

### P1 — 새로운 고장에 대한 검증 근거가 부족함

근거: `MODEL_CARD.md` 제한사항, `outputs/track_b_final_v2/run_manifest.json`, raw 라벨 집계.

- 지도 학습 이상 행은 16개, threshold/model selection에 쓰인 validation 이상은 **3행·3사건**뿐이다.
- 4종 모델이 validation F1=1.0으로 동률이다. 이 데이터로 후보 간 우열을 정밀하게 가릴 수 없다.
- locked test 이상은 **단일 장기 사건 1건**이다.
- 모델 카드가 네 시험 파일을 과거 실험에서도 사용했다고 명시한다. 이번 코드의 학습/검증 분리는 확인했지만, 과거 반복 실험에 따른 선택 편향까지 제거된 새 시험은 아니다.

조치: 기존 파일은 재사용 벤치마크라고 명시하고 새로운 독립 시험이라는 표현을 제한한다. 현 데이터에서는 파일/이상 유형을 보존한 여러 사전 정의 평가를 수행하고 결과 분산·미탐·오경보를 전부 공개한다. 단일 장기 사건을 여러 독립 사건으로 나누어 성능 신뢰도를 부풀리지 않는다. 새로운 고장 일반화 확인에는 새 날짜·새 설비·새 사건 데이터가 필요하며, 재학습만으로 해결되지 않는다.

### P2 — 설계서가 요구한 파일/용접 시퀀스 단위 판정 검증이 부족함

근거: 루트 설계서 PDF 4쪽; 현재 `calculate_metrics` 및 결과표는 주로 행/연속 이벤트 단위다.

그룹을 사이클 단위로 나눈 것은 좋지만, **사이클 단위로 분할하는 것과 사이클 단위 성능을 검증하는 것은 다르다.** 파일·사이클 OK/NG 정의와 실제 작업자가 받는 점검 알림의 승인 기준이 필요하다.

조치: 행 탐지기는 유지할 수 있다. 그 위에 사이클/이벤트 집계 정책, 경보 유지·해제·병합 정책을 정의하고 validation에서만 결정한다. locked 결과에는 행·사이클·이벤트별 TP/FP/FN, 탐지 지연과 오경보 빈도를 함께 제시한다. 정상 가동시간당 오경보를 계산할 때는 긴 수집 중단 시간을 가동시간으로 간주하지 않는다.

### P2 — 원본 시간 이상을 기록하지만 처리 규칙이 없음

근거: `split_historical_normal`은 파일 순서를 사용하고, `make_features`는 음수 시간 간격을 0으로 자른다. 원본 시간 역전은 6곳이며 1곳은 사이클 내부다.

기존 데이터 품질 산출물은 시간 역전을 집계하지만 학습 차단·격리·복구 정책은 없다. 시간순이라고 설명하는 범위를 '각 개발 파일 내부'와 '전체 운영 시점 검증'으로 나눠 설명해야 한다. 현재 정상 fit/calibration 경계는 날짜상 분리되어 있으므로 이를 경계 누수라고 부르지 않는다.

조치: raw 행 ID와 PageNo 순서를 보존하고 시간 역전 원인을 기록한다. 사이클 내부 역전은 임의 정렬로 고치지 말고 검토·격리 대상으로 둔다. 정상 사이클 정렬 및 제외 정책을 고정한 뒤 시간 특징에 미치는 영향을 검증한다. 별도 미래 시점 검증을 주장하려면 모든 학습·보정 데이터가 해당 시험의 예측 시점보다 과거여야 한다.

### P2 — 최종 모델 선택 근거의 코드·문서가 서로 다름

근거: `src/track_b_final_v2.py:516`, `:689`; `MODEL_CARD.md:28`; manifest의 `reverse_stress_used_for_selection=false`.

실제 코드는 validation 지표 동률 시 training_seconds를 비교한다. RobustPhaseZ는 이 값을 0.0으로 고정하므로 현재 동률을 이긴다. 단순한 모델을 택하는 것은 합리적이지만, 이것은 더 높은 검증 성능을 확인했다는 뜻이 아니다. 같은 측정 범위의 학습 비용 비교도 아니다.

모델 카드는 반대 방향 스트레스 테스트의 강건성 때문에 동률에서 이 모델을 선택했다고 설명하지만, 코드와 manifest는 해당 결과를 선택에 쓰지 않았다고 기록한다. 감사로 확인한 것은 **설명 불일치**이며, 역방향 시험을 실제로 선택에 사용한 누수가 있었다고 단정하지 않는다.

조치: 결과를 보기 전에 동률 규칙을 '단순성 우선' 등으로 명시하고 코드·계획·모델 카드를 일치시킨다. 계산 비용을 비교하려면 기준 생성·적합·추론의 측정 범위를 통일한다. 모델 선택을 저장한 뒤 시험을 실행하도록 절차와 기록도 분리한다.

## 7. '예지보전' 기능으로 표현할 수 있는 범위

현재 강점은 **용접 신호의 현재 이상 탐지와 점검 대상 선정**이다. 주력 모델은 같은 시점의 RealPower를 사용한다. 이상 첫 행에서 감지했다는 '탐지 지연 0'을 '고장 전에 예측했다'고 표현하면 안 된다.

HistoryOnly의 시험 Recall=0은 현재 측정값을 제외한 이 진단 모델이 해당 이상을 잡지 못했다는 뜻이다. 모든 미래 예측 방식이 불가능하다는 증명은 아니다. 현재 데이터에는 고장 발생 시점·정비 이력·명시적 예측 horizon/RUL 라벨이 없으므로, 고장 몇 시간 전 예측이나 잔여 수명을 검증했다고 주장할 근거가 없다.

현장 SOP가 없는 상황에서는 모델 근거와 일반 점검 제안을 보여줄 수 있지만, 실제 설비의 승인된 작업 절차라고 표시해서는 안 된다.

## 8. 권장 보완 순서와 완료 조건

1. **입력 오류 처리**: 잘못된 센서 데이터가 정상 판정으로 통과하지 않도록 고치고 실제 예측 진입점에서 회귀 검증한다.
2. **데이터·평가 계약 고정**: 사이클 ID/시간 이상/0 출력 처리, 파일 역할, 재사용 시험의 한계, 사건 단위 평가를 먼저 확정한다.
3. **운영 경보 정책 정의**: 단일 모델 또는 OR 조합, 사이클 판정, 경보 병합, 정상 가동시간의 정의와 오경보 기준을 정한다.
4. **현 데이터 내 재학습·재검증**: RobustPhaseZ를 기준으로 지도·비지도 후보를 같은 사전 정의 분할에서 비교한다. 모든 전처리와 임계값 결정은 각 분할의 학습/검증 자료만 사용한다. 제한된 사건 수를 유지한 채 파일 방향별 결과와 민감도를 공개한다.
5. **산출물 일치**: 선택 근거·모델 카드·전체 테스트를 정리하고 예측/평가/시드 결과를 같은 버전으로 재생성·검증한다. Firestore 게시 여부는 별도 작업이다.
6. **외부 검증은 별도 완료 조건**: 새로운 사건을 확보하기 전에는 '새 고장 일반화 검증 완료'라고 표시하지 않는다.

우선순위는 새로운 대형 모델 추가가 아니라 **입력 안전성 → 검증 설계 → 운영 단위 평가 → 필요한 재학습**이다. 현 상태의 RobustPhaseZ를 폐기해야 할 근거는 없으며, 신뢰할 수 있는 기준 모델로 보존하고 공정하게 비교하는 것이 적절하다.
